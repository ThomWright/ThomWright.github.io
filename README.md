# ThomWright.github.io

## Developing

### Run

The site is built by GitHub Pages using the `github-pages` gem. Run it locally with Docker, which installs the same gems:

```bash
docker compose up -d
```

The site, including drafts, is served at <http://localhost:4000/> and rebuilds when files change. The first start installs gems into a volume, so later starts are quick. Follow the logs with `docker compose logs -f`.

The container runs as UID/GID 1001 so that `_site/` stays owned by the host user. Change `user` in `docker-compose.yml` if yours differs (`id -u`).

Drafts without a `date:` are dated by their file's modification time, so editing one moves it to the top of the posts list.

Enable the pre-commit hook once per clone. It checks posts' front matter, as described in [Writing posts](#writing-posts).

```bash
git config core.hooksPath .githooks
```

### Generate the syntax highlighting styles

The light and dark themes are generated by Rouge and loaded for the matching `prefers-color-scheme`.

```bash
rougify style github > public/css/syntax/highlight.css
docker run --rm ruby:3.3-alpine sh -c "gem install rouge -v '~> 4.0' >/dev/null 2>&1 && rougify style github.dark" > public/css/syntax/highlight-dark.css
```

The bundled Rouge is too old to have `github.dark`, hence Docker for the dark theme. Rouge 5 needs a native extension that doesn't build on the Alpine image, hence `~> 4.0`.

### Generate the diagrams

Diagrams are inline SVGs in `_includes/diagrams/`, included in posts with `_includes/diagram.html`. Sequence diagrams, timelines and plots are written as TypeScript in `diagrams/sequences/`, `diagrams/timelines/` and `diagrams/plots/` and generated, and the rest are written by hand. GitHub Pages has no build step, so commit the SVGs.

After adding or editing any diagram, run:

```bash
node diagrams/build.ts
```

This regenerates the generated diagrams. It also adds two things to every diagram: fallback attributes for feed readers, which show diagrams without the site's CSS, and a width property the CSS uses to scale them. Node 24 runs the TypeScript directly, with no dependencies. The diagram formats are documented in `diagrams/sequence.ts`, `diagrams/timeline.ts` and `diagrams/plot.ts`, the fallbacks in `diagrams/fallbacks.ts`, and the house style in `public/css/_sass/_diagrams.scss`.

### Test the scripts

The scripts in `scripts/` check and update posts' front matter. Run their tests with:

```bash
node --test 'scripts/*.test.ts'
```

## Writing posts

### Give a post a description

Search results and link previews describe a post by its `description` front matter or, failing that, its excerpt: everything up to the first blank line. If a post opens with an epigraph, callout or anything other than a paragraph, give it a `description`, e.g. its opening sentence.

The pre-commit hook runs `node scripts/description.ts`, which lists posts that need one.

### Record changes to a post

When a published post changes substantively, add an entry to its `changes` front matter. The post header then shows "Updated" with the latest date, linking to a list of changes at the end of the post.

```yaml
changes:
  - date: 2026-10-03
    summary: Corrected the claim about restarts.
```

Then run:

```bash
node scripts/last-modified.ts
```

This copies the latest date into `last_modified_at`, which is where jekyll-seo-tag and jekyll-sitemap read a page's modified date. The pre-commit hook checks it's up to date.
